### [HIGH · XS] Claude Code v2.1.121 : option `alwaysLoad` sur les MCP servers, fini le coût Tool Search sur les MCPs critiques

**Source** — [GitHub Releases v2.1.121](https://github.com/anthropics/claude-code/releases/tag/v2.1.121) · [docs MCP](https://code.claude.com/docs/en/mcp)

Sortie le 28 avril, la v2.1.121 ajoute `alwaysLoad: true` au schéma de config MCP server. Quand activé, tous les tools du server skippent la déférence de Tool Search et restent toujours visibles à Claude. Disponible sur tous les types de servers (stdio, http, sse). Marquage par-tool aussi possible via `"anthropic/alwaysLoad": true` dans le `_meta` d'un tool individuel. Idée derrière la feature : Tool Search (lancé en janvier pour réduire 95% du contexte MCP) est génial sur les MCPs occasionnels mais coûte un round-trip extra sur les MCPs ultra-fréquents — alwaysLoad rend ce trade-off configurable.

> **How to apply** : pour MOI qui passe 80% des sessions Cowork à requêter Supabase pour le cockpit (lecture articles, écriture business_ideas, audit RLS), marquer le MCP Supabase comme `alwaysLoad: true`. Idem pour le MCP Atlassian côté mission RTE (transitions Jira). Laisser les MCPs occasionnels (Riot TFT, Strava observer, Hex auth) en mode lazy par défaut. Action concrète : éditer le bloc Supabase de la config Cowork, ajouter la ligne `"alwaysLoad": true`, redémarrer Cowork. Mesurer si les premières requêtes SQL passent du round-trip Tool Search à un appel direct (latence visible côté UX).

> **Trend** : 3ᵉ ajustement Claude Code MCP en 4 mois (Tool Search en janvier, MCP auto-retry x3 cette même semaine en v2.1.126, alwaysLoad). L'ergonomie MCP est explicitement priorisée par Anthropic — bon signal pour parier sur MCP comme couche d'intégration durable.

### [HIGH · S] `claude ultrareview [target]` non-interactif : multi-agent bug hunt en CI

**Source** — [Claude Code Docs - Code Review](https://code.claude.com/docs/en/code-review) · [Multi-Agent Bug Hunting Guide (Zen van Riel)](https://zenvanriel.com/ai-engineer-blog/claude-code-ultrareview-multi-agent-bug-hunting-guide/)

`/ultrareview` (slash command) déploie en cloud une flotte d'agents reviewers parallèles (5 par défaut sur PR standard, jusqu'à 20 sur gros diffs), chacun spécialisé : race conditions, SQL injection, error handling aux frontières, etc. Chaque finding doit survivre à une seconde passe d'agent qui tente de reproduire — réduit drastiquement le faux positif. Nouveauté de la semaine : le sous-commande non-interactive `claude ultrareview [target]` (sortie en v2.1.126 le 1ᵉʳ mai) bloque jusqu'à fin de la review, print les findings en stdout, exit code adapté pour scripting. Output JSON disponible. Timeout 30min par défaut configurable.

> **How to apply** : intégrer `claude ultrareview` dans un nouveau workflow CI `ultrareview-pr.yml` qui s'exécute sur les PRs touchant `pipelines/`, `cockpit/lib/supabase.js`, `jarvis/server.py`, et `sql/*.sql`. Démarrer non-bloquant (`continue-on-error: true`) pour mesurer le bruit pendant 2 semaines, puis durcir si le ratio signal/bruit tient. Compléter spec-drift-check (qui contrôle la cohérence doc-code) et lint-specs (qui bloque le vocabulaire technique en spec) — ultrareview couvre la dimension bug runtime que ces 2 checks ne voient pas. Coût à mesurer : Anthropic facture les agents reviewers, donc démarrer sur les paths sensibles uniquement, pas sur l'ensemble du diff.

> **Trend** : 2ᵉ commande Claude Code en 30 jours qui externalise le travail vers des agents cloud parallèles (Ultraplan en avril, Ultrareview en mai). Le pattern "thin client local + heavy parallel cloud" continue de se cristalliser.

### [HIGH · XS] "Claudy Day" — Oasis Security révèle 3 vulnérabilités chained sur claude.ai exploitables via Google Ads

**Source** — [Oasis Security blog](https://www.oasis.security/blog/claude-ai-prompt-injection-data-exfiltration-vulnerability) · [Dark Reading](https://www.darkreading.com/vulnerabilities-threats/claudy-day-trio-flaws-claude-users-data-theft) · [PDF Oasis](https://pages.oasis.security/rs/106-PZV-596/images/claudyday-vulnerability.pdf?version=0)

Oasis Security publie le détail d'une chaîne d'attaque baptisée "Claudy Day" sur claude.ai/claude.com. Trois failles : (1) prompt injection invisible via paramètres URL qui pré-remplissent la chat box (HTML hidden tags) ; (2) canal d'exfiltration via Anthropic Files API (un attaquant injecte sa propre API key dans le prompt caché, Claude scrape la conversation history et upload le payload sur le compte Anthropic de l'attaquant) ; (3) open redirect sur claude.com pour injecter des liens malveillants qui passent pour des résultats légitimes. Vecteur de delivery : annonce Google Ads pointant vers une URL claude.ai pré-remplie. **Statut** : prompt injection patchée par Anthropic avant publication, les 2 autres failles "are currently being addressed". Disclosure responsable via le programme Anthropic.

> **How to apply** : pour MOI qui clique sur des liens Claude depuis Slack/Gmail/recherches Google plusieurs fois par semaine, vigilance accrue temporaire jusqu'à patch complet : ne JAMAIS suivre un lien `claude.ai/?q=...` dont je ne reconnais pas l'origine, et particulièrement pas un lien promu par une publicité. Pour le cockpit qui n'expose aucune URL pré-remplie côté Claude, pas d'impact direct, mais la leçon générale s'applique : tout point d'injection user-controllable dans un prompt LLM est un vecteur potentiel de data exfiltration.

> **Trend** : 3ᵉ semaine consécutive avec une crise sécurité écosystème Claude (ToxicSkills v2 sur skills, MCP RCE "by design", désormais Claudy Day sur claude.ai lui-même). Le pattern : la couche client est systématiquement en retard sur la couche modèle. Anthropic patche vite quand l'attaque est démontrée, mais ne semble pas avoir un programme de red team systématique sur les surfaces nouvelles (pre-fill URL params, MCP loading, skill marketplace).

Anthropic a graduated Claude Security de research preview à public beta le 30 avril. Le tool scanne un codebase complet, identifie les vulnérabilités via raisonnement Opus 4.7 (data flow tracing, source code reading, interaction analysis entre composants), et propose des patches. Nouveautés ajoutées après le research preview : scheduled scans pour coverage continue, dismiss des findings avec raison documentée, exports CSV/Markdown pour intégrer dans les systèmes d'audit existants. Partenaires intégrant Opus 4.7 dans leurs plateformes : CrowdStrike, Palo Alto Networks, SentinelOne, Trend Micro, Wiz. **Disponibilité** : Claude Enterprise uniquement au lancement, Team et Max "in the near future".

> **How to install / apply** : pour MOI plan Pro perso, pas d'accès immédiat au lancement. Préparer le terrain : (a) lister les fichiers du cockpit qui justifieraient un scan dédié quand Team aura accès (`cockpit/lib/supabase.js` qui touche la JWT rotation, `jarvis/server.py` qui expose le tunnel, `pipelines/*.py` qui ingèrent du contenu externe, `sql/*.sql` qui définit RLS). (b) Préparer un benchmark contre les Supabase advisors actuels (déjà accessibles via `mcp__supabase__get_advisors`) — comparer les findings Claude Security vs Supabase advisors sur le même corpus quand on aura accès. (c) En attendant, utiliser le repo `anthropics/claude-code-security-review` (GitHub Action open-source) qui apporte la couche security review à Claude Code et tourne déjà sur Pro.

> **Trend** : Anthropic continue d'absorber les couches d'outillage qu'on bricolait à côté (Snyk, Veracode, SonarQube côté sec ; Figma côté design ; Cron côté scheduling).
